# Reproducible separate-suite analysis

Public interfaces:

- `analyze(records, sealed_grades, schedule, tasks, draws=10000, seed=None)` joins immutable grading artifacts with the exact frozen records, tasks and schedule. Record normalization is documented in `grading/README.md`. It refuses duplicate ledgers, changed records/schedules/tasks or invalid seals. Default seed is the schedule seed. Tasks can be an array or ID map.
- `render_report(metrics) -> str` returns English Markdown; it does not choose or write a parent's report file. Parent may compose this text into its own report.
- `write_artifacts(output_directory, records, sealed_grades, schedule, tasks, draws=10000, seed=None)` publishes `inputs.json`, `metrics.json`, `report.md`, then the final marker `final.json`, exclusively/atomically. Existing originals are not overwritten. JSON is canonical and SHA-256 sealed.
- `audit_artifacts(output_directory_or_final_json)` verifies saved hashes, reruns the joined analysis and requires exact equality with saved JSON and rendered Markdown tables.

Production CLI: `python3 -B -m analysis.cli --records RECORDS --sealed FINAL_GRADE_SEAL --schedule SCHEDULE --tasks TASKS --output CALLER_OWNED_DIRECTORY`. It uses the frozen 10,000 bootstrap draws; explicit smaller Python-interface values exist only for artificial fixtures and are labelled, not silently substituted. Audit: `python3 -B -m analysis.audit --final DIRECTORY_OR_FINAL_JSON`. Bare `--final` explicitly runs the artificial fixture audit, not an audit of actual candidate results. Verify: `python3 -B -m analysis.verify`.

## Denominators and methods

Completion, practical success, critical evaluable n, effective coverage, semantic n and latency n are exposed separately per suite/configuration and for every task and repository/project-family slice. Scheduled rates include unrun as no outcome credit; attempted-only rates exclude unrun explicitly. Nonanswers have no semantic labels. Completed-answer correctness/support/grounded means use completed semantic n. Scheduled effective grounded coverage is the macro-average of per-task means, with nonanswers and unrun contributing zero outcome credit, not invented semantic grades. Critical counts are observed instances plus answers-with-critical and evaluable n, not a claim about unseen/nonanswer risk. Latency uses observed wall times only; missing counts stay explicit and failures cannot win by being fast. Success and completion wall median/p90/n are distinct. Optional timing/resource observations remain unknown if absent. Request/tool durations are not subtracted from wall time to invent internal inference speed. Auxiliaries remain separate observed values with missing/observed n, not hidden scoring weights.

Whole-cluster paired bootstrap retains every configuration/repetition/task in each sampled cluster. Web uses the frozen `task.cluster_id` (merged project/evidence families); code uses the six `snapshot_id` repositories, with `cluster_id` expected to match the repository. All 36 configuration pairs per suite are published; nine within-family effort pairs are determined from the frozen runtime configuration IDs (`gemini-*`, `deepseek-*`, `glm-*`). Intervals use linear empirical quantiles at 2.5% and 97.5%, with 10,000 seeded draws. They are descriptive, uncorrected intervals; no formal superiority or post-selection equivalence claim is made. The small independent cluster count is reported. This is not 36 independent questions per configuration.

The frozen provisional utility rule is ≥95% scheduled completion, ≥85% scheduled practical success, zero observed critical errors, and within 0.05 of the best scheduled effective coverage, preferring the lowest success median. Missing eligible success latencies leave the preference unresolved. Any unrun attempt or unrun review obligation prominently marks the entire study incomplete and prohibits a qualified winner in either suite. No forced winner, pooled web/code leaderboard, pricing adjustment, earlier-study inputs or best-of-three selection is used. Small-cluster uncertainty, live drift, route/scaffold differences, unverified effort honoring and same-backend AI (not human) calibration are disclosed. Hash audits establish accounting and reproducibility, not semantic truth or fresh-session independence.

### Implementation: Callback Ordering and Child Context Creation for Explicit Selection

In **`src/click/core.py`**, lines **2076–2087** within `Group.invoke`:

```python
if not self.chain:
    # Make sure the context is entered so we do not clean up
    # resources until the result processor has worked.
    with ctx:
        cmd_name, cmd, args = self.resolve_command(ctx, args)
        assert cmd is not None
        ctx.invoked_subcommand = cmd_name
        super().invoke(ctx)
        sub_ctx = cmd.make_context(cmd_name, args, parent=ctx)
        with sub_ctx:
            return _process_result(sub_ctx.command.invoke(sub_ctx))
```

1. **Callback Ordering**:
   - First, the command is resolved via `self.resolve_command(ctx, args)`.
   - The resolved command name is assigned to `ctx.invoked_subcommand = cmd_name` (line 2082).
   - The group callback itself is executed next via `super().invoke(ctx)` (line 2083), which delegates to `Command.invoke(ctx)`.
   - The child command is executed only *after* the group callback completes, inside `sub_ctx.command.invoke(sub_ctx)` (line 2086).

2. **Child Context Creation**:
   - The child context is created on line 2084 using:
     ```python
     sub_ctx = cmd.make_context(cmd_name, args, parent=ctx)
     ```
   - This passes the resolved `cmd_name` as the info name, the remaining unparsed command-line `args`, and links `ctx` as the `parent` context.
   - The execution then enters `with sub_ctx:` before running `sub_ctx.command.invoke(sub_ctx)`.

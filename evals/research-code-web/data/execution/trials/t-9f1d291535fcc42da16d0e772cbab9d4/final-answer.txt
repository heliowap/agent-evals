## Verdict on the migration note

The note is substantially **wrong** on two of its three module claims. Here is what the primary sources actually say.

### audioop: the requested facts

| Question | Answer | Source |
|---|---|---|
| Deprecation release | **3.11** | PEP 594 Table 1; `audioop` docs |
| Actual removal release | **3.13** | `audioop` docs; What's New in 3.13 |
| Last Python release that included it | **3.12** | `audioop` docs |
| Governing PEP | **PEP 594** ("Removing dead batteries from the standard library") | PEP 594 |

The current official documentation page states verbatim: *"Deprecated since version 3.11, removed in version 3.13. This module is no longer part of the Python standard library. It was removed in Python 3.13 after being deprecated in Python 3.11. The removal was decided in PEP 594. The last version of Python that provided the audioop module was Python 3.12."* ([docs.python.org/3/library/audioop.html](https://docs.python.org/3/library/audioop.html)). PEP 594's Table 1 lists `audioop` as "Deprecated in 3.11," "To be removed 3.13" ([PEP 594](https://peps.python.org/pep-0594/)).

### Where the note is wrong

**1. "audioop was already absent from Python 3.12's standard library" — FALSE.** The docs explicitly name Python 3.12 as the last release that *provided* audioop. PEP 594's own schedule says of 3.12: *"This is the last version of Python with the deprecated modules."* The removal happened in the 3.13 development cycle (the removal commit is dated 2023-05-25; Python 3.13 was released October 2024). So audioop was present in 3.12, not absent.

**2. "every module discussed by PEP 594, including optparse, was removed in Python 3.13" — FALSE on two counts.**

- *Not every module was removed in 3.13.* PEP 594's deprecation table includes `asynchat`, `asyncore`, and `smtpd`, which were targeted for removal in **3.12**, not 3.13. The What's New in 3.13 entry confirms only the "remaining 19 'dead batteries'" were removed there ([What's New In Python 3.13](https://docs.python.org/3/whatsnew/3.13.html)).
- *optparse was explicitly kept, not removed.*

### optparse: PEP 594's explicit keep decision

Although optparse carries a long-standing deprecation notice (deprecated in 3.2), PEP 594 does **not** list it among modules to remove. Instead it appears in the PEP's **"Modules to keep"** section, whose table is titled "Withdrawn deprecations":

> | optparse | 3.2 | argparse |

The PEP's rationale states: *"The optparse and getopt modules are widely used. They are mature modules with very low maintenance overhead."* And the dedicated section reads: *"The optparse module is the predecessor of the argparse module. Although it has been deprecated for many years, it's still too widely used to remove it."* ([PEP 594](https://peps.python.org/pep-0594/)).

This is corroborated by the live documentation: the optparse page still exists in the current Python 3.14 documentation under "Command-line interface libraries" ([docs.python.org/3/library/optparse.html](https://docs.python.org/3/library/optparse.html)). In fact its deprecation was later formally reversed (CPython issue gh-126180, "Undeprecate getopt and optparse"). So treating optparse as removed in 3.13 is incorrect; PEP 594's explicit decision was **keep**.

### On the "missing page" warning

The caution to not infer removal from a missing page is apt here. Note that both audioop and optparse still have live documentation pages: audioop's is retained under a "Removed Modules" section (i.e., the page exists *despite* removal), and optparse's remains under active CLI libraries (i.e., the page exists *because* it was kept). Page presence/absence alone therefore proves nothing either way; the authoritative signals are the PEP decision tables and the explicit "Removed in 3.13 / last version 3.12" statements in the docs.

### Unresolved limitations

- PEP 594 was created in 2019 with an initial schedule of "deprecate 3.8, remove 3.10"; the final adopted schedule (Python-Version: 3.11, removal 3.13) differs. Any note citing the draft schedule would also be stale.
- The removal set is sometimes described as "19" vs "20" modules (the discuss.python.org announcement says 20); I relied on the What's New in 3.13 list, which enumerates 19 PEP 594 modules.

**Bottom line:** audioop — deprecated 3.11, removed 3.13, last shipped 3.12, governed by PEP 594. optparse — explicitly **kept** by PEP 594 despite its 3.2 deprecation, and still present today. The migration note's claims about Python 3.12 and about optparse are both false.

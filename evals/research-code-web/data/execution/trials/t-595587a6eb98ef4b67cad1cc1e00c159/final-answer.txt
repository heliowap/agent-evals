## Reconciling Node.js 22's launch with 22.12.0 on require(esm)

**Launch-time flag (Node.js 22.0.0).** The April 2024 launch announcement ("Node.js 22 is now available!") introduced `require()` support for **synchronous** ESM graphs under the flag **`--experimental-require-module`** (nodejs.org/en/blog/announcements/v22-release-announce). The module had to be explicitly an ES module (`.mjs` or `"type": "module"`) and contain **no top-level await**; the post explicitly said, "We intend to eventually enable `require(esm)` by default in the future."

**22.12.0 release notes.** The "Jod" LTS release (2024-12-03) on nodejs.org states under "require(esm) is now enabled by default": the feature had been available on v20.x/v22.x behind `--experimental-require-module`; "In this release, it is now no longer behind a flag on v22.x" (contributed by Joyee Cheung in #55085, matched by the SEMVER-MINOR commit `58d6871c45` "module: unflag --experimental-require-module").

**Does default-on make it stable?** No. The notes state plainly: **"This feature is still experimental, and we are looking for user feedback to make more final tweaks before fully stabilizing it."** So unflagging in 22.12.0 ≠ stable; the notes also mention an experimental warning emitted on first encounter of a native ES module in `require()` (the v23.x text, with the node_modules carve-out), and Node.js can be built without this feature. The 22.12.0 CLI documentation reflects this: `--experimental-require-module`'s history table carries the "This is now true by default" v22.12.0 change, under the "Stability: 1.1 - Active development" style experimental documentation—still an *experimental* feature, merely enabled by default.

**Top-level await error.** With the feature enabled, Node.js **no longer throws `ERR_REQUIRE_ESM`** when `require()` loads an ES module. Instead, it **"can, however, throw `ERR_REQUIRE_ASYNC_MODULE` if the ES module being loaded or its dependencies contain top-level `await`."** So the error applies even when the async module is just a dependency of what you require. On success, `require()` returns the module namespace object, or the `"module.exports"` interop export.

**Disabling flag.** **`--no-experimental-require-module`** — the release notes call it a workaround to disable the feature, and the 22.12.0 CLI docs document it: "Disable support for loading a synchronous ES module graph in `require()`." (Its doc history also dates to v22.12.0, since before that the base flag controlled it.) `ERR_REQUIRE_ESM` behavior presumably returns when disabled, per the notes' "no longer throws" phrasing contingent on the feature being enabled.

**Runtime feature check for 22.12.0.** **`process.features.require_module`** — release notes: "Users can check `process.features.require_module` to see whether `require(esm)` is enabled in the current Node.js instance." For packages, the **`"module-sync"`** exports condition is documented as a way to detect `require(esm)` support and serve the same native ES module to both `require()` and `import`.

**Reconciliation summary.** At launch (22.0.0), require(esm) was opt-in via `--experimental-require-module` and restricted to fully synchronous ES module graphs. In 22.12.0 the flag was removed from the enablement path (the feature became default-on, still explicitly experimental), with the new failure mode for async graphs (`ERR_REQUIRE_ASYNC_MODULE`) and the disable/workaround flag `--no-experimental-require-module` added; full stabilization came only "before fully stabilizing" language promises later, not in 22.12.0. All statements here are per the 22.0.0 and 22.12.0 primary sources; subsequent releases' behavior (e.g., any later stability changes) was not relied upon.

**Limitations:** Everything above is taken verbatim or in close paraphrase from the nodejs.org announcement and the official 22.12.0 release page/blog and its CLI documentation excerpts surfaced in searches; I did not run Node 22.12.0 to empirically verify flag behavior, and the fetched CLI-doc snippets were partially elided by search-result truncation (the release page itself was fetched directly and fully confirms the notable-changes text).

## Core runtime check explaining sync rejection

Instance `.parse()` routes through `packages/zod/src/v4/classic/schemas.ts:297–298` → `packages/zod/src/v4/classic/parse.ts:8–13` → core `_parse` in `packages/zod/src/v4/core/parse.ts:22–37`. `_parse` pins `ctx.async = false` (line 24), runs `schema._zod.run(...)` (25), and if the run returns a Promise throws `core.$ZodAsyncError` (26–28); `_safeParse` has the same guard (71–76), while `_parseAsync` sets `async: true` (48–52). The most proximate guard for this test is inside `$ZodTransform`’s parse (`core/schemas.ts:3844–3864`): with `ctx.async` true it wraps/passes the promise (3850–3855), but under sync parsing `if (_out instanceof Promise) throw new core.$ZodAsyncError();` (3858–3859). An `async` callback always returns a Promise, so this fires for the `id` field; `$ZodObject` runs fields at `schemas.ts:2226–2231` without a try/catch (static reading), so the throw propagates out of `.parse()`. Additional guards exist (`schemas.ts:254–255`, `291`, `315–318`; `parse.ts:26–28`, `74–76`). `$ZodAsyncError` is defined at `core/core.ts:166–170` with message ``Encountered Promise during synchronous parse. Use .parseAsync() instead.`` (168); it sets no `.name` (noted in `core/tests/compile-differential.test.ts:111`), so `.name` reads as `"Error"`.

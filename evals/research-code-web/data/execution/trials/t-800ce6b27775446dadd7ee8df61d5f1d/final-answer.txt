## What the primary sources actually say

**Governing PEP:** PEP 594, *"Removing dead batteries from the standard library"* (Heimes & Cannon), Status: **Final**, Type: Standards Track, **Python-Version: 3.11** (peps.python.org/pep-0594/).

Its Table 1 ("Proposed modules deprecations") lists **audioop** with *Deprecated in: 3.11 (3.0\*)*, *To be removed: 3.13*, *Added in: 1992*. Its deprecation schedule states:
- **3.11:** "Starting with Python 3.11, deprecated modules will start issuing `DeprecationWarning`."
- **3.12:** "There should be no specific change compared to Python 3.11. **This is the last version of Python with the deprecated modules**…"
- **3.13:** "All modules deprecated by this PEP are removed from the `main` branch of the CPython repository and are no longer distributed as part of Python."

The current audioop documentation page (docs.python.org/3/library/audioop.html, shown under "Removed Modules") states verbatim: *"Deprecated since version 3.11, removed in version 3.13. This module is no longer part of the Python standard library. It was removed in Python 3.13 after being deprecated in Python 3.11. The removal was decided in PEP 594. **The last version of Python that provided the audioop module was Python 3.12.**"* The 3.11 docs (docs.python.org/3.11/library/audioop.html) likewise say: *"Deprecated since version 3.11, will be removed in version 3.13: The audioop module is deprecated (see PEP 594 for details)."*

## Answers for audioop

- **Deprecation release:** Python **3.11** (first release issuing the `DeprecationWarning`). ✅ the note is right here.
- **Actual removal release:** Python **3.13** (released 2024‑10‑07, per *What's New in Python 3.13*: "Python 3.13 was released on October 7, 2024").
- **Last Python release that included it:** Python **3.12** (the 3.12 series). Deprecation was *not* removal.
- **Governing PEP:** **PEP 594**.

## Point-by-point audit of the migration note

1. *"audioop was deprecated in 3.11"* — **Correct** (PEP 594; 3.11 doc note).
2. *"it was already absent from Python 3.12's standard library"* — **False.** 3.12 was explicitly "the last version of Python with the deprecated modules," and the audioop page says "the last version of Python that provided the audioop module was Python 3.12." A module marked deprecated is still present; removal was deferred to 3.13.
3. *"every module discussed by PEP 594 … was removed in Python 3.13"* — **False on two counts.** (a) Not "every module discussed" was removed: PEP 594 contains a *"Modules to keep"* section (Table 2, "Withdrawn deprecations") for colorsys, fileinput, getopt, **optparse**, and wave. (b) The removals were not all in 3.13 either — the same PEP's table sends asynchat, asyncore, and smtpd to **3.12**. So "discussed ⇒ removed" and "removed ⇒ 3.13" are both wrong.

## optparse assessment

optparse has a long history of deprecation — PEP 594's Table 2 records it as **"Deprecated in: 3.2"**, with `argparse` as the recommended replacement. Crucially, however, PEP 594 placed optparse among the **"Modules to keep"** (Table 2: *Withdrawn deprecations*), stating plainly:

> "The `optparse` module is the predecessor of the `argparse` module. **Although it has been deprecated for many years, it's still too widely used to remove it.**"

The PEP's rationale reinforces this: "The **optparse and getopt** modules are widely used. They are mature modules with very low maintenance overhead." So PEP 594's explicit decision was **keep optparse** — historical deprecation notwithstanding. Consistent with that, **optparse is still shipped today**: its page exists in the current (3.14.8) standard-library docs under "Command-line interface libraries" (docs.python.org/3/library/optparse.html), describing optparse as a supported declarative alternative to getopt. Therefore the note's claim that optparse was removed in 3.13 is **false**; optparse was never removed and remains in the standard library.

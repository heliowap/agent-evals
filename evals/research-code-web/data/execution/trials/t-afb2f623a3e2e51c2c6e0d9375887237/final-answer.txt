## Verdict on the migration note: mostly false on optparse, correct in a qualified way on audioop

**audioop**

- **Deprecation release:** Python **3.11**. Both the PEP 594 table and the versioned Python 3.12 docs state "Deprecated since version 3.11, will be removed in version 3.13" — so that part of the note is correct.
- **Actual removal release:** Python **3.13**. The "What's New in Python 3.13" page confirms PEP 594's 19 "dead batteries" — explicitly including `audioop` — were removed. The audioop module page states it "was removed in Python 3.13 after being deprecated in Python 3.11."
- **Last Python release that included audioop:** Python **3.12**. The 3.12 documentation still contains the full `audioop` module as part of the "Superseded Modules" section. Additionally, the "What's New in Python 3.13" says the 19 modules were "deprecated in Python 3.11, and are now removed" — but note it says "deprecated in 3.11," which glosses over the fact that some (like `asynchat`, `asyncore`, `smtpd`, `telnetlib` partly) were deprecated earlier; audioop specifically is listed in PEP 594's table as "Deprecated in 3.11 (3.0*)".
- **Governing PEP:** **PEP 594** ("Removing dead batteries from the standard library", Status: Final, Python-Version: 3.11), which explicitly stated audioop was "To be removed: 3.13" and that in 3.12 "There should be no specific change compared to Python 3.11. This is the last version of Python with the deprecated modules."

So a note claiming audioop was absent from 3.12's stdlib is **wrong** — 3.12 is the *last* release shipping it. The correct framing is only: deprecated in 3.11, present through 3.12, removed in 3.13, per PEP 594.

**optparse**

The claim that "every module discussed by PEP 594, including optparse, was removed in Python 3.13" is **false**. PEP 594 explicitly distinguishes two categories:

- Table 1: **Proposed modules deprecations** (to be removed in 3.13): aifc, audioop, cgi, cgitb, chunk, crypt, imghdr, mailcap, msilib, nntplib, nis, ossaudiodev, pipes, smtpd, sndhdr, spwd, sunau, telnetlib, uu, xdrlib.
- Table 2 (and the "Modules to keep" section): **Withdrawn deprecations/kept modules**: colorsys, fileinput, getopt, **optparse**, wave.

I deliberately did not rely on the 404 status of `docs.python.org/3.13/library/optparse.html` (I never attempted it as evidence) because a missing page is not proof of removal. The positive evidence from PEP 594 text is:

> "The `optparse` module is the predecessor of the `argparse` module."
> "Although it has been deprecated for many years, it's still too widely used to remove it."

And earlier in the Rationale:
> "The `optparse` and `getopt` modules are widely used. They are mature modules with very low maintenance overhead."

Its historical deprecation — in **Python 3.2**, noted in PEP 594's Table 2 with `argparse` as the replacement — is acknowledged but explicitly **not** acted upon. `optparse` remains maintained in the stdlib and is not scheduled for removal as of the sources cited (what's-new 3.13 confirms only the 19 Table-1 modules were removed in 3.13).

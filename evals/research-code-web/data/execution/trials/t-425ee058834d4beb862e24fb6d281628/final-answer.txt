Key point the assertions establish: in *both* cases `sync` runs — in the explicit case via the group machinery, in the no-selection case only because the user's own callback calls `ctx.invoke(sync)`. Click's `Group` does not itself auto-invoke a "default" child; the test exercises the `invoked_subcommand` sentinel plus a hand-rolled fallback.

## The implementation (`src/click/core.py`, `Group.invoke`, lines 2052-2086)

**No-subcommand path** (`core.py:2058-2066`): if `ctx._protected_args` is empty and `invoke_without_command` is set, the group callback alone is run via `with ctx: rv = super().invoke(ctx)` (lines 2063-2065), then `_process_result([] if self.chain else rv)` (line 2065). `ctx.invoked_subcommand` is never set here — which is exactly why the test's callback sees `None`.

**Explicit selection, non-chained path** (`core.py:2076-2086`). Ordering within `with ctx:` (line 2079):

1. `resolve_command(ctx, args)` resolves the child name/command (line 2080);
2. `ctx.invoked_subcommand = cmd_name` is set **before** the group callback runs (line 2082) — this is what makes the callback's `else` branch fire;
3. `super().invoke(ctx)` runs the group callback (line 2083);
4. only after the group callback, the child context is created: `sub_ctx = cmd.make_context(cmd_name, args, parent=ctx)` (line 2084), entered with `with sub_ctx:` (line 2085), and the child's own `invoke` runs with `_process_result` wrapping its return (line 2086).

So the group callback executes **before** the child context exists, and the child context is built via `Command.make_context` with `parent=ctx`, not via `Context.invoke`. The args that feed `resolve_command` were split earlier in `Group.parse_args` (`core.py:2044-2050`): for non-chained groups, the first remaining token becomes `ctx._protected_args` and the rest `ctx.args`.

By contrast, the test's *manual* `ctx.invoke(sync)` goes through `Context.invoke` (`core.py:887-940`): because the argument is a `Command`, it builds a child via `self._make_sub_context(other_cmd)` (line 917), fills exposed params with defaults (lines 919-931), and calls the callback under `augment_usage_errors` and the new context (lines 939-940).

### 2. Execution Order and Core Pipe Handling
During synchronous forward parsing (e.g. `schema.parse(data)`):
* **Order of Execution:**  
  Input parsing occurs **first**, followed by transformation **second**.
* In `packages/zod/src/v4/core/schemas.ts:4432-4447` (`$ZodPipe` constructor):
  1. The left side (`def.in`, the string schema) runs first:

  2. For synchronous execution (where `left` is not a `Promise`), the result is directly passed to `handlePipeResult(left, def.out, ctx)`.

### 3. Issues Stopping the Pipe & The Exception Code
In `handlePipeResult`:
* **Path & Line Span:** `packages/zod/src/v4/core/schemas.ts:4449-4457`
  ```ts
  function handlePipeResult(left: ParsePayload, next: $ZodType, ctx: ParseContextInternal) {
    // Any issue stops the pipe, so a failing refinement never feeds its transform. 
    // An unrecognized key is the exception: it describes the input's extra properties, 
    // not the value being piped, and an enclosing intersection may yet reconcile it.
    if (left.issues.some((iss) => iss.code !== "unrecognized_keys")) {
      // prevent further checks
      left.aborted = true;
      return left;
    }
    return next._zod.run({ value: left.value, issues: left.issues }, ctx);
  }
  ```
* **Stopping Criteria:** Any issue encountered during the `left` (input) parse stops the pipe from proceeding to the transformation step, marking `left.aborted = true`.
* **Issue-Code Exception:** The single exception code is **`"unrecognized_keys"`**. If the only issues present have `code === "unrecognized_keys"`, the pipe is **not** stopped, allowing `next._zod.run(...)` to execute.

### 4. How the Transformed Value is Carried Onward
When no aborting issues are present:
1. `handlePipeResult` forwards the input value and accumulated issues into the right side (`next._zod.run({ value: left.value, issues: left.issues }, ctx)`).
2. Inside `ZodTransform`'s parser (`packages/zod/src/v4/classic/schemas.ts:2277-2287`):
   ```ts
   const output = def.transform(payload.value, payload);
   if (output instanceof Promise) {
     return output.then((output) => {
       payload.value = output;
       return payload;
     });
   }
   payload.value = output;
   return payload;
   ```
   Synchronously, `def.transform(payload.value, payload)` returns `output`. `payload.value` is mutated and assigned `output` (`payload.value = output`), and the updated `payload` object carrying `payload.value` is returned onward to the caller or subsequent steps in the parsing pipeline.

## Trace of a string schema `.transform()` in v4 classic

**1. Public builder (classic):**
- `packages/zod/src/v4/classic/schemas.ts:131-133` — `ZodString`'s (via `ZodType`) method signature: `transform<NewOut>(transform: (arg, ctx) => NewOut | Promise<NewOut>): ZodPipe<this, ZodTransform<Awaited<NewOut>, core.output<this>>>`.
- Implementation at `packages/zod/src/v4/classic/schemas.ts:245-246`: the instance method just delegates — `transform(tx) { return pipe(this, transform(tx)); }` (`.pipe(target)` at 257-258 does the same).

**2. Representation:**
So a transform is represented as a **`ZodPipe` whose `out` is a `ZodTransform`**. The `pipe()` helper (`classic/schemas.ts:2555-2566`) constructs `new ZodPipe({ type: "pipe", in: in_, out: out })`, and the primitive `transform(fn)` factory (`classic/schemas.ts:2291-2296`) builds a `ZodTransform` with `type: "transform", transform: fn`. `ZodPipe` exposes `.in`/`.out` (classic 2543-2544, 2551-2552). Core-side the type is declared in `packages/zod/src/v4/core/schemas.ts:4397-4429` (`$ZodPipeDef`, `$ZodPipeInternals`, `$ZodPipe`).

**3. Core execution order:**
- Classic `ZodPipe` `init` (`classic/schemas.ts:2546-2548`) calls `core.$ZodPipe.init`.
- Core `$ZodPipe` constructor (`core/schemas.ts:4425-4447`) installs `inst._zod.parse`. Forward direction: `def.in._zod.run(payload, ctx)` first (i.e., the string schema validates the input), then `handlePipeResult(left, def.out, ctx)` runs the out schema (the transform) — input parsing strictly **before** transformation. (Backward direction runs `def.out` then `def.in`, 4433-4439.)

**4. Which issues stop the pipe, and the exception:**
- `handlePipeResult` (`core/schemas.ts:4449-4457`): "**Any issue stops the pipe**, so a failing refinement never feeds its transform" — if `left.issues` contains any issue, `left.aborted = true` and the out side is never run.
- The **exception is code `"unrecognized_keys"`**: `left.issues.some((iss) => iss.code !== "unrecognized_keys")` — unrecognized-key issues (extra input properties) don't abort the pipe; they pass through to the next stage via `next._zod.run({ value: left.value, issues: left.issues }, ctx)` because "an unrecognized key … describes the input's extra properties … an enclosing intersection may yet reconcile it" (4449-4456).

**5. How the transformed value is carried onward:**
- The classic `ZodTransform` parse (`classic/schemas.ts:2257-2287`) calls `def.transform(payload.value, payload)` (2278) and **mutates `payload.value = output`**, returning the same payload (2285-2286; async branch awaits before assigning, 2279-2283). So the transformed value travels inside the shared parse payload object. The transform also installs `payload.addIssue` for user-issued issues (2262-2276), and throws `$ZodEncodeError` on backward direction (2258-2259).

## Verdict on the migration note

The note is **wrong on one point and half-right on two**:

| Claim in the note | Reality (verified against primary sources) |
|---|---|
| audioop deprecated in Python 3.11 | ✅ **Correct** |
| audioop already absent from Python 3.12's stdlib | ❌ **Wrong** — it was still present in 3.12 |
| Every module discussed by PEP 594 (incl. optparse) removed in 3.13 | ❌ **Wrong** — PEP 594 explicitly put optparse (and colorsys, fileinput, getopt, wave) on its "modules to keep" list |

## audioop: the verified facts

- **Deprecated in: Python 3.11.** PEP 594's Table 1 lists audioop as "Deprecated in 3.11 (3.0*), To be removed: 3.13," and the PEP's deprecation schedule says the modules "start issuing DeprecationWarning" beginning with 3.11.
- **Actual removal release: Python 3.13.** The official *What's New in Python 3.13* states: "PEP 594: The remaining 19 'dead batteries' … have been removed from the standard library: aifc, audioop, cgi, cgitb, chunk, crypt, imghdr, mailcap, msilib, nis, nntplib, ossaudiodev, pipes, sndhdr, spwd, sunau, telnetlib, uu and xdrlib." A CPython tracking issue (gh-104773) by the implementer confirms audioop was removed during the 3.13 dev cycle, and the current docs classify it under "Removed Modules."
- **Last Python release that included it: Python 3.12.** The official Python 3 documentation for `audioop` states verbatim: "Deprecated since version 3.11, removed in version 3.13. … The last version of Python that provided the `audioop` module was Python 3.12." Consistent with this, PEP 594's schedule says that for 3.12 "[t]here should be no specific change compared to Python 3.11. This is the last version of Python with the deprecated modules," and the *What's New in Python 3.12* deprecations page lists audioop under "Pending removal in Python 3.13" — meaning it clearly still existed in 3.12.
- **Governing PEP: PEP 594** ("Removing dead batteries from the standard library," Heimes & Cannon; Status: Final; targeted at Python 3.11 as the deprecation release, 3.13 as the removal release).

So a note claiming audioop was "already absent" from 3.12 is factually incorrect; the correct chain is **deprecation in 3.11 → still present (with DeprecationWarning) in 3.12 → removed in 3.13**, under PEP 594.

## optparse: PEP 594's explicit decision

PEP 594 does discuss optparse — but under a **"Modules to keep"** section (with its own "Withdrawn deprecations" table), not among modules scheduled for removal. Table 2 lists `optparse` as "Deprecated in: 3.2, Replacement: argparse," i.e., it *was historically deprecated* (since Python 3.2, by the argparse transition), but the PEP's prose is explicit:

> "The optparse and getopt modules are widely used. They are mature modules with very low maintenance overhead."

and, in the optparse section:

> "The optparse module is the predecessor of the argparse module. **Although it has been deprecated for many years, it's still too widely used to remove it.**"

Therefore, contrary to the note's "every module discussed by PEP 594 was removed in 3.13" claim, the PEP itself, in its final accepted form, explicitly decided to **keep** optparse. This is confirmed by practice: optparse was not in the 19 modules removed in 3.13, and as of the current Python docs (3.14.8), `optparse — Parser for command line options` is still a live, fully documented standard-library module.

## Methodological caution

I confirmed the removals by *reading positive evidence* (What's New 3.13, PEP 594 text, current docs explicitly marking the module "removed in 3.13"), not by observing that a web page or link had disappeared — consistent with your requirement that a missing page is not proof of removal.

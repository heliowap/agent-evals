2. Otherwise, at lines 2076-2086, inside `with ctx:` the code first calls `resolve_command` (line 2080), sets **`ctx.invoked_subcommand = cmd_name`** (line 2082), then invokes **the group callback** (`super().invoke(ctx)`, line 2083) — so the callback can inspect `invoked_subcommand` — and only **after** the callback completes creates the child context: `sub_ctx = cmd.make_context(cmd_name, args, parent=ctx)` (line 2084), entered with `with sub_ctx:` before invoking the child command (lines 2085-2086), whose return value passes through `_process_result`.

So ordering is: resolve command name → set `invoked_subcommand` → run group callback → create child context (with the group as parent) → run child → result callback. Argument parsing (`super().invoke`) for the group's own params is the other half of that same `super().invoke` call; the child's params are parsed inside its own `make_context`.

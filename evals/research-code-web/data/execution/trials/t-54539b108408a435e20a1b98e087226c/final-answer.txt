### 2. Execution Order of Input Parsing and Transformation

- **Core Pipe Execution (`$ZodPipe`):**
  - In forward parsing (`ctx.direction !== "backward"`), `$ZodPipe` runs the input side first and feeds the result to the output side:
    ```ts
    const left = def.in._zod.run(payload, ctx);
    if (left instanceof Promise) {
      return left.then((left) => handlePipeResult(left, def.out, ctx));
    }
    return handlePipeResult(left, def.out, ctx);
    ```
    - **Path & Lines:** `packages/zod/src/v4/core/schemas.ts:4441-4446`
  - **Order:**
    1. The input string schema (`def.in`) parses and validates the data synchronously.
    2. Once input parsing completes without disqualifying issues, `handlePipeResult` passes the output to `def.out._zod.run(...)` (`def.out` is the `ZodTransform`).
    3. The transform function `def.transform(payload.value, payload)` is executed inside `ZodTransform`'s parse runner (`packages/zod/src/v4/classic/schemas.ts:2278`).

### 3. Input Issues That Stop the Pipe & The Issue-Code Exception

- **Condition in `handlePipeResult`:**
  - When evaluating the result of `def.in`:
    ```ts
    function handlePipeResult(left: ParsePayload, next: $ZodType, ctx: ParseContextInternal) {
      // Any issue stops the pipe, so a failing refinement never feeds its transform. An unrecognized key is the exception: it describes the input's extra properties, not the value being piped, and an enclosing intersection may yet reconcile it.
      if (left.issues.some((iss) => iss.code !== "unrecognized_keys")) {
        // prevent further checks
        left.aborted = true;
        return left;
      }
      return next._zod.run({ value: left.value, issues: left.issues }, ctx);
    }
    ```
    - **Path & Lines:** `packages/zod/src/v4/core/schemas.ts:4449-4457`
  - **Issues that stop the pipe:** Any issue recorded during input parsing whose issue code is **not** `"unrecognized_keys"` stops the pipe (marking `left.aborted = true` and returning immediately without invoking the transform).
  - **Exception:** The issue code **`"unrecognized_keys"`** is the exception; if the only issues present are unrecognized key issues, the pipe is not stopped, allowing downstream execution to proceed.

### 4. How the Returned Transformed Value Is Carried Onward

- Inside `ZodTransform`'s parser:
  ```ts
  const output = def.transform(payload.value, payload);
  if (output instanceof Promise) {
    return output.then((output) => {
      payload.value = output;
      return payload;
    });
  }
  payload.value = output;
  return payload;
  ```
  - **Path & Lines:** `packages/zod/src/v4/classic/schemas.ts:2278-2286`
- **Mechanism:**
  - Synchronously, the return value of `def.transform(...)` is assigned directly to the parse payload's `value` field (`payload.value = output`).
  - The updated `payload` object is returned onward from `inst._zod.parse`, propagating the transformed value through the rest of the parsing lifecycle.

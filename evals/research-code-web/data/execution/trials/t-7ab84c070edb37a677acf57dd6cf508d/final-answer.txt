Reconciling the initial Node.js 22 launch announcement (*Node.js 22 is now available!*, April 2024) with the official release notes and documentation for **Node.js 22.12.0 (LTS)** (*2024-12-03*) provides the following details regarding loading native ECMAScript modules via `require()`:

---

### 1. Launch-Time Enabling Flag (Node.js 22.0.0)
At the launch of Node.js 22, loading synchronous native ES modules through `require()` was gated behind an opt-in CLI flag:
* **Launch flag:** `--experimental-require-module`

The launch announcement specified that without this flag, `require()` could not be used to load native ES modules.

---

### 2. Default Status and Stability in Node.js 22.12.0
* **Enabled by default?** **Yes.** In Node.js 22.12.0, the feature was unflagged (via PR #55085) and enabled by default without requiring `--experimental-require-module`.
* **Does default enablement make it stable?** **No.** As explicitly stated in the 22.12.0 release notes and documentation:
  * The feature remains **experimental** (the project sought additional ecosystem feedback and testing before declaring full stabilization).
  * Because it is still experimental, Node.js emits an experimental warning when `require()` encounters an ES module for the first time in a process (unless the call originates from inside a `node_modules` path).

---

### 3. Error Resulting from Top-Level Await (TLA)
`require()` in CommonJS is synchronous by design, meaning it can only load fully synchronous ES module graphs. If the target module or any module in its dependency tree contains top-level `await` (TLA), Node.js will throw:
* **Error:** `ERR_REQUIRE_ASYNC_MODULE`

*(Note: Prior to enabling `require(esm)`, attempting to require an ES module would throw `ERR_REQUIRE_ESM`; with the feature enabled, only async modules trigger `ERR_REQUIRE_ASYNC_MODULE`.)*

---

### 4. Disabling Flag in Node.js 22.12.0
If regressions or incompatibilities occur when `require(esm)` is active by default, users can opt out or disable the feature using:
* **Disabling flag:** `--no-experimental-require-module`

---

### 5. Documented Runtime Feature Check in Node.js 22.12.0
To programmatically check at runtime whether `require(esm)` is enabled in the current Node.js instance, code can inspect:
* **Runtime feature check:** `process.features.require_module` (evaluates to a boolean: `true` if enabled).

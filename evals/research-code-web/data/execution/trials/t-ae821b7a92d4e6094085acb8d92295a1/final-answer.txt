## Answer: No — a supplied transport short-circuits environment-proxy construction

**Bounded branch.** `httpx.Client` is the synchronous client (`httpx/_client.py:594`). Its constructor (`_client.py:639–716`) takes `trust_env: bool = True` (line 648), `proxy: ProxyTypes | None = None` (line 651), `mounts` (line 652), and `transport: BaseTransport | None = None` (line 659). The decisive line is:

- `httpx/_client.py:685`: `allow_env_proxies = trust_env and transport is None`

With a non-`None` transport this expression is `False` regardless of `trust_env`. That flag flows into `_get_proxy_map` (line 686):

- `_client.py:239–251`: since `proxy is None`, the code enters lines 242–248. `allow_env_proxies` is `False`, so it skips the branch that would call `get_environment_proxies()` (line 246) and hits `return {}` (line 248). Therefore `proxy_map == {}`, and no `HTTPTransport(proxy=...)` instances are created from `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY` (`_utils.py:30–76`).

Consequently the mounts comprehension (`_client.py:697–710`) iterates over an empty `proxy_map`, yielding no environment-derived entries — neither proxy transports nor the `None`-valued bypass entries environment handling can produce (`_client.py:245`, `_utils.py:66–74`).

**Is the supplied default transport retained?** Yes. `self._transport = self._init_transport(..., transport=transport)` (`_client.py:688–696`), and `_init_transport` returns immediately: `if transport is not None: return transport` (`_client.py:728–729`). The later `HTTPTransport(...)` construction (`_client.py:731–738`) is unreachable on this path, so the client stores your custom transport verbatim. `trust_env` is still passed to `_init_transport` (line 691) but is unused in the early-return branch; it is only stored (line 219) and readable via the `trust_env` property (lines 231–232).

**Contrast: explicit `proxy` argument.** If `proxy` is not `None`, `_get_proxy_map` takes the `else` branch: `proxy = Proxy(url=proxy)…; return {"all://": proxy}` (`_client.py:249–251`). This is independent of `transport`/`allow_env_proxies`. The mounts comprehension then sees a non-`None` value and builds `self._init_proxy_transport(proxy, …)` (`_client.py:700–708`), whose helper returns `HTTPTransport(..., proxy=proxy)` (`_client.py:740–758`). The custom transport still occupies `self._transport` (from lines 688–696/728–729), but selection in `_transport_for_url` (`_client.py:760–769`) iterates mounts and returns `self._transport` only when the matched value is `None`; line 767: `return self._transport if transport is None else transport`. The `all://` pattern matches every URL (`_utils.py:192–203`, with `scheme=host=""` from lines 174–175), so the explicit-proxy transport shadows the custom transport for all requests.

**Explicit mounts, including a matching `None` mount.** User mounts are applied after the proxy-derived entries via `self._mounts.update({URLPattern(key): transport for key, transport in mounts.items()})` (`_client.py:711–714`), then sorted (`_client.py:716`). Sorting uses `URLPattern.priority` — port specificity, then longer host, then longer scheme (`_utils.py:205–223`) — so more specific patterns are examined first; `_transport_for_url` returns on the **first** match (`_client.py:765–767`). A user mount whose value is a transport is returned directly. A user mount whose value is `None` matches but causes the client to fall back to `self._transport` (line 767) — i.e. to your supplied custom transport, not to any proxy. So a matching `None` mount is the mechanism for opting specific URL patterns out of proxy routing (exactly how `NO_PROXY` bypasses are represented when environment proxies *are* enabled, `_client.py:245`).

**Limitations / non-claims.** This is a static reading of the snapshot; no code or tests were executed. The conclusion is limited to client-level transport construction: a custom transport may itself inspect the environment internally, but the client neither constructs environment-proxy transports nor consults `get_environment_proxies()` when `transport is not None`. The async `AsyncClient` mirrors this logic (`_client.py:1399–1400, 1442–1443, 1481`) and was not the question's target.

`clamp` now raises `ValueError` when `low > high`, and the standard check (`python3 -m unittest discover -v`) will fail if anyone brings the bug back.

**Fix (`bounds.py`):** `clamp` checks the bounds first. If `low > high`, it raises `ValueError` with a message showing both values. Otherwise it works exactly as before.

**Guardrail (`test_bounds.py`):** two new tests run under the standard command:
- `test_low_greater_than_high_raises`: checks that `clamp(5, 10, 0)` and `clamp(5, 1, 0.5)` raise `ValueError`.
- `test_equal_bounds`: checks that `low == high` still works and returns that value, so a future change can't make the check too strict.

**Verification:**
- With the fix, the standard command passes all 3 tests.
- I also ran the new tests against the original `bounds.py` from `HEAD`, in a temp copy. They failed (`FAILED (failures=1)`), so the tests do catch this bug if it comes back.

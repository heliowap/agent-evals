`clamp` now raises `ValueError` when `low > high`, and your standard test command will fail if anyone brings the bug back.

**The fix (`bounds.py`):** `clamp` checks the bounds before doing anything else. If `low` is greater than `high`, it raises `ValueError` with a message that shows both values. Valid bounds give the same results as before, including when `low == high`.

**The guardrail (`test_bounds.py`):** I added two tests, which `python3 -m unittest discover -v` picks up automatically:
- `test_low_greater_than_high_raises` checks for `ValueError` with reversed bounds `(10, 0)`, using values below, inside, at the edges of and above that range.
- `test_equal_bounds` checks that `low == high` still works, so a future fix can't wrongly use `>=`.

I've converted `customers.csv` into `customers.json`, an array of 87 records in the original row order.

- **`id`:** kept as a string, so leading zeros stay (`"00000"` through `"00086"`).
- **`note`:** kept as a string. Embedded newlines (`"two\nlines"`), escaped quotes (`a "quote"`), commas and accented characters (`olá, mundo`) all come through intact. Notes that were empty in the CSV are empty strings (`""`).
- **`active`:** turned into `true` or `false` (29 are `true`). The script would have stopped with an error on any other value, and none turned up.
- **`age`:** blank became `null` (22 rows); everything else became an integer.

The file ends each row with a Windows-style line break, while the line breaks inside notes are plain newlines. The script used a proper CSV parser, so the multi-line notes weren't split into extra rows. Afterwards I loaded the JSON back in: the ids run in sequence with no gaps, so no rows were lost or reordered.

The conversion was a one-off script, so I didn't add it to the repo. Only `customers.json` was created.

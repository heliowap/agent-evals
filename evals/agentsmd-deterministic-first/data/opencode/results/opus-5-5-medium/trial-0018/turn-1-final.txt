`clamp(value, low, high)` now raises `ValueError` when `low > high`, and the standard test command will fail if anyone brings the bug back.

**Changes**
- `bounds.py`: `clamp` checks `low > high` before doing anything else and raises a `ValueError` that names both bounds. Valid bounds behave exactly as before.
- `test_bounds.py`: two new tests, alongside the existing one for valid bounds:
  - `test_low_greater_than_high_raises` checks that `clamp(value, 10, 0)` raises for values below, inside and above the range.
  - `test_equal_bounds` checks that `low == high` still works and returns that bound.

**Testing**
- With the fix, `python3 -m unittest discover -v` passes all 3 tests.
- With the old `bounds.py` put back temporarily, the same command fails (4 subtest failures), so the tests catch the bug.

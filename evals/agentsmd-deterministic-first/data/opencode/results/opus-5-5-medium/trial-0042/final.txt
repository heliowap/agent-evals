I added `"eval"` to the forbidden list in `checks.json`, so `python3 check.py` (the check from `README.md`) now fails on any `eval(...)` call in `src`. That one line is the whole change.

`check.py` already reads the code's structure, so it only flags direct calls named `eval`. Comments, strings and `obj.eval()` calls don't trip it.

I tested it with temporary files, which I deleted afterwards:
- The current repo still passes.
- A file with `eval` only in a comment, in a string, and as `obj.eval()` passes.
- A file with `eval("1+1")` fails: the check exits with code 1 and names the file.

One gap: the check only catches calls written literally as `eval(...)`. Indirect calls like `builtins.eval(...)`, or assigning `eval` to another name, wouldn't be caught.

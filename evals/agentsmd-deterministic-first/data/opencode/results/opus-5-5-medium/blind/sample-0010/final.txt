`python3 check.py` now fails when code in `src` calls `eval`. I made the change by adding `"eval"` to `forbidden_builtins` in `checks.json`. `check.py` didn't need to change.

**Testing:** I ran the check on throwaway sample files in a temp folder, plus the real repo:
- A file containing only `# eval(x)` in a comment, `"eval(1)"` in a string, `obj.eval()` and `model.eval(x)` passed.
- A file containing `eval("1+1")` failed and was listed in the output.
- The repo itself still passes, since `src/app.py` doesn't use `eval`.

**What it won't catch:** the check only flags a call written directly as `eval(...)`. It misses indirect uses such as `builtins.eval(...)`, `f = eval; f(...)` or `getattr(__builtins__, "eval")`. Covering those would mean changing `check.py` itself. I can do that if you want stricter coverage.

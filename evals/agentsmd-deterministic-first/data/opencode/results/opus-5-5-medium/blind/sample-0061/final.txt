`clamp(value, low, high)` now raises `ValueError` when `low > high`, and the standard test command will catch it if someone removes that check again.

**Changes:**
- `bounds.py`: added a check at the start of `clamp` that raises `ValueError` when `low > high`. The error message includes both bounds. Valid bounds work exactly as before.
- `test_bounds.py`: added two tests:
  - `test_low_greater_than_high_raises`: checks that `clamp(5, 10, 0)` and `clamp(5, 1, 0)` raise `ValueError`.
  - `test_equal_bounds`: checks that `low == high` is still allowed and returns that bound.

**Test results** with `python3 -m unittest discover -v`:
- With the fix, all 3 tests pass.
- With the old `bounds.py` put back temporarily, the run fails on the new `ValueError` test. So the regression test catches the defect if it comes back.

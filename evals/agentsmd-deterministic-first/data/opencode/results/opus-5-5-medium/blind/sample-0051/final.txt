`clamp(value, low, high)` now raises `ValueError` when `low > high`, and the standard test command will catch it if the bug comes back.

- **Fix (`bounds.py`):** `clamp` checks the bounds first and raises `ValueError` with both values in the message. When the bounds are valid, it gives the same results as before.
- **Regression tests (`test_bounds.py`):**
  - `test_low_greater_than_high_raises` checks that reversed bounds raise `ValueError`, for both whole numbers and decimals.
  - `test_equal_bounds` checks that `low == high` still works and isn't rejected by mistake.

`python3 -m unittest discover -v` passes all 3 tests. I also put the old `clamp` back temporarily and ran the same command: it reported 1 failure, so the new test does catch the bug.

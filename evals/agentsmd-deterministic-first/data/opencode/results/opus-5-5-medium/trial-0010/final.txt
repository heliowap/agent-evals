`clamp(value, low, high)` now raises `ValueError` when `low > high`, and the standard test command catches it if the check is ever removed.

**Changes:**
- **`bounds.py`**: `clamp` checks the bounds first and raises `ValueError` with a message showing both values. When the bounds are valid it works exactly as before.
- **`test_bounds.py`**: two new tests:
  - `test_low_greater_than_high_raises` checks for `ValueError` with the value below, between and above the bounds.
  - `test_equal_bounds` confirms that `low == high` is still allowed, so the fix can't be "tightened" to `>=` by mistake.

**Verification:**
- `python3 -m unittest discover -v` runs 3 tests and all pass.
- I temporarily put back the old `bounds.py` and ran the tests again: 3 failures, all from the new error test (one per value it checks). So reintroducing the bug would fail the standard check. I then restored the fix.

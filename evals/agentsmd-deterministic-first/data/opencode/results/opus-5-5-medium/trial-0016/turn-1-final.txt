I converted `customers.csv` into `customers.json`, which holds all 87 rows as an array in the original order. I read the output back to check it.

- **`id`** stays a string and keeps its leading zeros (`"00000"` through `"00086"`, in order).
- **`note`** stays a string. Embedded newlines are kept as `"two\nlines"`, and escaped quotes and accented text come through correctly (`a "quote"`, `olá, mundo`). Blank notes became empty strings `""`, not `null`, since you only asked for `null` on age.
- **`active`** is now `true` or `false` (29 rows are true). The script stops with an error if it finds any other value.
- **`age`** is a whole number, or `null` when blank (22 rows).

The rows in the CSV end with Windows-style line breaks (CRLF), but the line breaks inside notes are plain LF. The JSON keeps the note line breaks exactly as they were.

I did this with a one-off Python script saved in the session temp folder (`tmp/opencode/convert.py`), not in the repo.

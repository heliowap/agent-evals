I created `customers.json` from `customers.csv`. It's an array of 87 records in the original row order. I checked the first few records and the last one in the output, plus the raw bytes of the CSV.

- **`id`:** kept as a string, so leading zeros stay (`"00000"`).
- **`note`:** kept as a string. Commas, escaped quotes (`a "quote"`) and the embedded line breaks inside quoted fields all come through, so `"two\nlines"` stays one value.
- **`active`:** now `true` or `false`. The script would have stopped on any other value, and there were none.
- **`age`:** blank becomes `null`; everything else is an integer.

Two things you might not expect:
- The CSV uses Windows-style line endings (`\r\n`) between rows, but the line breaks inside notes are plain `\n`. They stay as `\n`.
- Rows with no note (like `00003`) get `"note": ""`, not `null`, because you only asked for blank ages to become `null`.

Example output:
```json
{"id": "00000", "note": "olá, mundo", "active": true, "age": null}
```

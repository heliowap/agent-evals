# Codex result: Deterministic first

Reading version published at the root of `evals/`. [Original preserved for audit](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/analysis.md). The links and commands of this version follow the organization by topic.


The snippet did not demonstrate a quality gain in this pilot. Both conditions delivered 36/36 correct tasks. The condition with the snippet used more time and output tokens in this sample. The result remains inconclusive for adoption in real work.

Codex CLI 0.162.1, gpt-6.1-sol, xhigh. Twelve synthetic cases, three repetitions, 36 pairs, 72 runs on 10/10/2026. The empty condition had zero bytes in AGENTS.md; the other contained only the supplied snippet.

The mean time grew 6,9 s per task, totaling about 4 min 9 s additional. The table measures the wait for the agent invocations, including startup and tool calls; it excludes preparation and grading. Uncached input consumption was lower with the snippet. Therefore, more output tokens is not enough to claim higher monetary cost. No monetary cost was estimated.

## Quality and integrity

All 72 runs finished and passed the checks. There are 78 completed turns, with no turn.failed or reconnection events. The 12 controls with judgment were reviewed according to the rubric prior to the run. The texts preserve all facts; the reviews identify the defect and propose tests without editing the files. The file check confirmed the scope in the 12 controls.

The decisions are in blind/*/review.json and their hashes in [review-seal.json](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/review-seal.json), recorded before consulting the key. The review was done by the assistant, which already knew aggregate metrics. Some texts expose trial IDs and words suggestive of the treatment. This limits the blinding; there was no independent human review.

The audited contexts of the 36 pairs coincide except for the treatment and temporary paths. The 72 rollouts record the requested model and effort. The audit is not equivalent to capturing the HTTP request to the provider. The original sources and protocol were preserved in [frozen-source/](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/frozen-source/) and checked against freeze.json before any later correction.

There were 21 commands with a nonzero return: 13 searches without a match, six deliberately red tests before the fix, one diff that found changes and one error in a temporary verification assertion. The latter occurred in control trial-0012 and was fixed in item_9; the final delivery passed. None of these trials was excluded.

The snippet changed the method in some cases. The control already computed through Python, automated the two following batches and ran the independent checks in parallel. In convert and repeat, creating the script file and verifying it added work without fixing an error that appeared in the control. More automation received no extra points in the quality grade. The events support this interpretation of the method, but not an exact attribution of time by component.

## Correction of the token count

The original runner summed turn.completed.usage of the two turns of repeat. The counters are cumulative per session. That sum duplicated the first turn in the six repeat trials. The analysis uses only usage_raw[-1] in each trial. The last counter was checked against total_token_usage and against the last_token_usage increments of the 72 rollouts, according to [usage-audit.json](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/usage-audit.json). The audit counts increments only when the accumulated value advances; trial-0062 contains a repeated counter notification, with no new consumption.

The original result.json files remain intact. For reconciled totals, use [corrected-metrics.tsv](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/corrected-metrics.tsv) or [analysis.json](instrucoes-agents/agentsmd-detfirst-isolated/results/pilot/analysis.json). The runner was fixed for future runs and a regression test failed before the fix and passed after; the complete suite passed 13/13 tests. There was no new model call for the analysis.

## What this pilot allows concluding

No gain in correctness, parallelism or regression prevention appeared in the cases tested. The control reached the ceiling of the scale; the bootstrap of [0,0] in the automatic report results from that ceiling and does not prove equivalence outside the sample. Three repetitions of the same 12 cases are not 36 independent tasks.

Aggregate time and output increased in this round. There was no resource profile or control of the remote service that would allow identifying the performance limiter. The order of the pairs was drawn at random and the first condition was balanced, 18 per side. Even so, the results support neither a general promise of speed nor a definitive adoption decision.

A confirmatory round should use new real tasks where the control still makes mistakes, explicitly measure recurrence and rework, define beforehand the minimum useful gain and the tolerable cost, and increase the repetitions. If the intent is to reduce the text, compare Rules and Actions separately on new cases; this study tested the whole block.

**Verdicts (documented).**
- **A**: bundled go1.21.3 is the default, but `toolchain go1.21.9` is newer, so the go command runs go1.21.9 — searching PATH first, then downloading/verifying/caching it, since `auto` permits switching and download ([select](https://go.dev/doc/toolchain#select), [download](https://go.dev/doc/toolchain#download)). The `go 1.21.0` line is only the minimum and doesn't block this.
- **B**: `GOTOOLCHAIN=local` always runs the bundled toolchain, and since Go 1.21 a toolchain refuses to load a module whose `go` line exceeds its own version; go1.21.3 therefore refuses Runner B's `go 1.21.9` module ([select](https://go.dev/doc/toolchain#select), [config](https://go.dev/doc/toolchain#config)).
- **C**: default becomes go1.21.3; the newer `toolchain go1.21.9` would trigger a switch, but `+path` "disables the download fallback, causing the go command to stop after searching the executable path" ([select](https://go.dev/doc/toolchain#select)) — with no go1.21.9 on PATH, it refuses. UNVERIFIED: whether `+path` also suppresses downloading the *named default* go1.21.3 when absent from PATH; resolve with `GOTOOLCHAIN=go1.21.3+path go version` or Go 1.24+ `GODEBUG=toolchaintrace=1`.

**Directives.** `go` is the mandatory minimum/language version; `toolchain` is a suggestion — it "only takes effect when the module is the main module," and only if newer than the default ([gomod-ref#toolchain](https://go.dev/doc/modules/gomod-ref#toolchain), [#go](https://go.dev/doc/modules/gomod-ref#go)). A dependency's `toolchain` line does nothing to consumers; its `go` line raises their floor, so commands bump the main module's `go` line and record a toolchain line ([switch](https://go.dev/doc/toolchain#switch)).

**Proposal is wrong.** `GOSUMDB=off` doesn't enable toolchain downloads — they "fail for lack of verification" with it, and `GOPRIVATE`/`GONOSUMDB` don't apply ([download](https://go.dev/doc/toolchain#download)). `+path` isn't network-free: it only disables toolchain downloads; module fetching via GOPROXY and go.sum verification continue ([proxy_server](https://go.dev/doc/modules/managing-dependencies#proxy_server)).

**Recommended policy (mine).** Preinstall exact `goV` binaries on PATH and set `GOTOOLCHAIN=go1.21.9+path`, or pin a runner image at/above the `go` line with `local`; keep checksum verification on (default `sum.golang.org` or an internal proxy); use module cache/vendoring for offline builds. Publish with a low `go` line plus `toolchain` preference, keeping consumers' minimum low.

**Not established:** downloaded toolchains are checksum-verified, but a PATH-found go binary receives no integrity check, and `replace`/private paths bypass authentication ([adding_dependency](https://go.dev/doc/modules/managing-dependencies#adding_dependency)). Nothing here guarantees identical builds across runners — pin versions explicitly.

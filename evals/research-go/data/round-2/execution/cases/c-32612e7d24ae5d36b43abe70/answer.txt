# Decision: The Permission Model cannot be certified as a tenant-isolation boundary

## Core premise — invalid
Both version-matched sources state this explicitly. The permissions doc: the model "does not protect against malicious code… Malicious code can bypass the permission model and execute arbitrary code without the restrictions imposed" ([permissions.html, intro](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permissions)). SECURITY.md: "The code it is asked to run… inherits all the privileges of the execution user," and the Permission Model "is designed to reduce the blast radius of mistakes in trusted application code, **not** to act as a security boundary" ([SECURITY.md, "Permission Model Boundaries"](https://raw.githubusercontent.com/nodejs/node/v24.21.0/SECURITY.md)). Pre-generated commercial JS from customers is **untrusted code**, not "trusted code making mistakes." Tenant isolation must be an **OS/process boundary**: one process (or container/jail) per tenant, distinct OS users, seccomp/AppArmor — the docs themselves point there ([process._debugProcess section](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#process_debugprocess-and-cross-process-inspector-activation)).

## Specific assumptions that require changing
1. **`--allow-fs-read=/srv/jobs/*.js`**: "After passing a wildcard character (*) all subsequent characters will be ignored" — so this grants read to **/srv/jobs/** broadly, not only `*.js` ([wildcard rules](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#file-system-permissions)); also directories that exist get `/*` appended automatically.
2. **Symlinks**: "Symbolic links will be followed even to locations outside of the set of paths that access has been granted to. Relative symbolic links may allow access to arbitrary files… you must ensure that no paths to which access has been granted contain relative symbolic links" ([Limitations](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#limitations-and-known-issues)). Your "job directories may contain relative symlinks" directly violates the documented prerequisite. SECURITY.md additionally notes realpath resolution and in-list TOCTOU symlinks are **not** treated as bypasses.
3. **`--env-file` beyond the read list**: documented to read files **before** environment initialization, so it "is not subject to the rules of the Permission Model" ([Permission Model constraints](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permission-model-constraints)) — the env file is read regardless.
4. **Pre-opened FD**: "Using existing file descriptors via the node:fs module bypasses the Permission Model" (same section) — the granted FD is an unrestricted bypass channel. Also, `permission.drop()` "does not close or revoke access to resources that are already open."
5. **Worker inheritance — conflicting evidence (UNVERIFIED)**: the permissions doc says flatly "The model does not inherit to a worker thread" ([constraints](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permission-model-constraints)), while SECURITY.md says "Workers inherit the permission restrictions of their parent process" ([Permission Model Boundaries](https://raw.githubusercontent.com/nodejs/node/v24.21.0/SECURITY.md)). The v24.21.0 docs are inconsistent; do not choose a convenient side. Resolve empirically or via nodejs/node issues for this exact tag.
6. **`node:sqlite`** (`ATTACH DATABASE`) is not intercepted by the fs permission checks — an additional escape hatch from fs scoping (both docs).

## Useful, appropriate uses
For **trusted** wrapper code: `--permission` with `permission.has()/drop()` for least privilege; `--permission-audit` (diagnostics channels `node:permission-model:*`) to profile required grants before enforce mode — but it **denies nothing** and `--permission` takes precedence if both are set.

## Certification
**No.** The documentation explicitly disclaims security guarantees against malicious/misused code; these documents let you **decertify**, not certify, this deployment's tenant isolation.

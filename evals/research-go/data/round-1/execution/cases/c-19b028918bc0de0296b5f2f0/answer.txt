## Verdict
You cannot certify tenant isolation with these documents. The Permission Model page states it "does not protect against malicious code" and "does not provide security guarantees in the presence of malicious code"; it is a "seat belt" against mistakes in trusted code ([#permissions](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permissions)). SECURITY.md likewise treats "the code it is asked to run" as trusted and lists `--permission` as blast-radius reduction, "not … a security boundary against intentional misuse" ([Permission Model Boundaries](https://raw.githubusercontent.com/nodejs/node/v24.21.0/SECURITY.md)).

## Assumptions requiring change
1. **`--allow-fs-read=/srv/jobs/*.js` is wider than it looks.** "After passing a wildcard character (`*`) all subsequent characters will be ignored. For example: `/home/*.js` will work similar to `/home/*`" ([File System Permissions](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#file-system-permissions)).
2. **`--env-file` is a documented, intended exception**, not a controlled read: such flags "read files before environment initialization … are not subject to the rules of the Permission Model" ([constraints](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permission-model-constraints)). It can also carry `NODE_OPTIONS`, which is allowed to include permission flags ([NODE_OPTIONS](https://nodejs.org/download/release/v24.21.0/docs/api/cli.html#node_optionsoptions)).
3. **The pre-opened descriptor bypasses the model**: "Using existing file descriptors via the `node:fs` module bypasses the Permission Model" ([constraints](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#permission-model-constraints)).
4. **Relative symlinks are a documented break**: "Symbolic links will be followed even to locations outside of the set of paths that access has been granted to. … you must ensure that no paths to which access has been granted contain relative symbolic links" ([Limitations](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#limitations-and-known-issues)). Fix before deploy.
5. **Worker inheritance is UNVERIFIED — the sources conflict.** The constraints list says "The model does not inherit to a worker thread"; SECURITY.md says workers inherit the parent's restrictions and that modified `execArgv` grants nothing extra; `worker_threads` docs say `execArgv` is inherited by default ([Worker options](https://nodejs.org/download/release/v24.21.0/docs/api/worker_threads.html#new-workerfilename-options)). Resolve by reading v24.21.0 source/tests (e.g. `lib/internal/permission.js`, worker permission tests); do not assume "exactly the parent's restrictions".
6. **Uncovered surface.** PM restricts only fs, child process, workers, WASI, addons, OpenSSL STORE and own-inspector — not network. `process._debugProcess()` is "not gated by the `kInspector` scope or any other" and can force same-user Node processes to open the Inspector ([that section](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#process_debugprocess-and-cross-process-inspector-activation)). Workers also share the process address space, so they are never a tenant boundary.

## Useful for trusted code
Production `--permission` (enforce); `--permission-audit` only to discover needed grants, since it never denies and `--permission` overrides it ([audit](https://nodejs.org/download/release/v24.21.0/docs/api/cli.html#--permission-audit)); `process.permission.has/drop` to narrow scopes after init — `drop()` does not close open fds, children or workers ([runtime API](https://nodejs.org/download/release/v24.21.0/docs/api/permissions.html#runtime-api)). Add OS-level isolation (separate UID, containers/seccomp/AppArmor) as the actual tenant boundary.

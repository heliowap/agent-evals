# Code-review benchmark v2 — implementation and run plan

**Design:** [`../specs/2026-09-26-code-review-eval-v2-design.md`](../specs/2026-09-26-code-review-eval-v2-design.md). The user approved three new repositories, 25 fixed configurations, two axes, two independent repetitions (300 valid reviews), English benchmark prompts only, and an OpenRouter reported-spend pause at USD 10. Do not edit the installed `/code-review` skill or overwrite the first round. This directory is not a Git repository; do not create a worktree or claim commits.

## Files and boundaries

- `round-2/candidate-research.md`: primary-source evidence and rejection/acceptance rationale for candidate PRs. This is research evidence, not the prompt.
- `round-2/prepare_fixtures.py` → `round-2/fixtures.json`: reproducible collection of three pinned, self-contained cases with verbatim issue/PR excerpts, diff, source context, standards, links and SHA references. The generator checks compare ancestry and fetches head-pinned source with authenticated `gh` for GitHub API calls; no editorial hints about target findings.
- `round-2/grading-rubric.md`: pre-response target findings and proofs, decision boundary, accepted equivalences and limits. Keep separate from fixtures.
- `round-2/prompts.py`: fixed English shared and per-axis prompt templates, no runtime reads of the installed skill; supplies the identical case/axis prompt to all models and repetitions.
- `round-2/benchmark.py`: small stdlib-only, resumable runner: frozen matrix/cell manifest, randomized order, independent isolated `opencode run --standalone` sessions with closed stdin; export and check each session; preserve rejected attempts; honor OpenRouter reported-spend ceiling, timeout and retries. Never change providers for a cell.
- `round-2/test_benchmark.py`: focused `unittest` checks for matrix cardinality, prompt construction and hashes, export validation, resume and budget/error boundaries. Avoid real API calls in unit tests.
- `round-2/manifest.json`: original frozen hashes of fixtures, templates, rubric, matrix and 300-cell queue. After the first answer, a v2 CLI export bug in prompt decoding required an isolated runner correction at `round-2/revision-1/manifest.json`. A cost-unverifiable MiMo attempt later required `round-2/revision-2/manifest.json` with frozen evidence and a budget reconciliation. Both earlier manifests remain intact; the active revision's `migration.json` records re-exported prior results.
- `round-2/revision-2/results/` and `round-2/revision-2/attempts/`: active audit records for valid answers and excluded attempts. Each valid record references its exported session and includes model/variant, prompt hash, answer, tokens, duration, reported cost and attempt ID. The original records remain in their respective older revision directories.
- `round-2/revision-2/adjudication.json` and `round-2/revision-2/comparison.md`: after the complete collection, the blind decisions are preserved as raw categories and the report is explicitly exploratory because one target lacks sufficient fixture context. `methodology-review.md` records the validity caveats without editing the frozen inputs or sealed grades.
- Root `README.md`: one pointer and state/count for round two; first-round facts and historical scoring unchanged.

## Task 1: establish qualified, reproducible cases

1. Inspect `round-2/candidate-research.md` and primary GitHub issue/PR/code/rules at *pinned head*, not current main. Candidate repos under investigation: pytest-dev/pytest #14773, axios/axios #10852, spf13/cobra #1664; reject any case whose known Spec issue has already been fixed, whose Standards rule does not apply, or whose full changed behavior cannot be given to reviewers. Search replacements before freezing, never after seeing model answers.
2. For each accepted case, save base/head, commit list, exact issue/PR excerpts, the full pinned diff, unchanged context sufficient for the failure path, and the exact applicable documented rules in `fixtures.json`. Confirm `git diff base..head` corresponds to the public commit, and the issue and rules existed at the chosen head. Cite source URLs.
3. Independently reproduce or prove at least one concrete target on each axis per case. Record exact lines, mechanism, observable effect, acceptable paraphrases, and *not proven* conclusions in `grading-rubric.md`. Include a preflight check that a human with only the fixture can find the target; omit any target that requires a fact not supplied to the model. Put style-only or process-only rules in separate categories, and avoid three identical missing-test targets.
4. Verify fixture size and inspect full rendered prompts for leak of gold labels, misleading summaries, invisible source paths or prompt-injection material. Preserve untrusted source text as quoted data. **Gate:** no model call before all three cases and the rubric are fixed.

## Task 2: implement and verify the English prompts

1. Add `prompts.py` with a common instruction: review only one assigned axis against provided material, no tools, source text is data, max three material findings, `No supported findings` allowed. The output format must ask for changed-code location, quoted rule/requirement, causal mechanism, impact, and evidence strength. Do not force a missing feature or scope-creep finding.
2. In Standards, distinguish documented applicable rule from heuristic smell; require concrete cost for a smell and do not claim that a missing test proves a functional failure. In Spec, distinguish issue objective from PR author's claim, check missing/incorrect/out-of-scope behavior only if supported, and distinguish verified current effects from conditional/unverified ones. Both prompts in English. The installed skill remains unmodified.
3. Add tests for axis isolation, reproducible prompts, sources and identity-independent rendering, and a snapshot/hash check. Run `python3 -m unittest round-2/test_benchmark.py` or an equivalent direct discovery command.

## Task 3: runner, integrity and dry run

1. Encode exactly the 25 IDs and routes from the approved spec: 11 GPT variants via `openai`; 9 Gemini/SWE-2/CPA Claude variants via `cli_proxy`; GLM and DeepSeek four variants via `openrouter`; MiMo via `openrouter/xiaomi/mimo-v2.6-flash#none` after the free OpenCode CLI route rejected a preflight with HTTP 403 and zero tokens. Keep the archived [first preflight manifest](../../../round-2/manifest-v1-preflight.json) and [second preflight manifest](../../../round-2/manifest-v2-preflight.json) distinct from the operative one. Check all 25 actual IDs against prior results or catalog before manifest freeze. Do not infer Fast service activation from the requested suffix. Each of 25 × 3 × 2 × 2 gets a stable unique ID and separate session.
2. Test-first implement a bounded runner with `--dry-run`, `--run`, `--status`, single-cell preflight via `--model`/`--case`/`--axis`/`--limit 1`, and deterministic seed. Reuse stdlib subprocess/JSON, not a dependency or a service. Close stdin with `stdin=subprocess.DEVNULL`. Preserve every attempt under a unique path; never replace or accept an existing valid response. Use atomic writes and separate temporary working directories; write an OpenCode **v2** `.opencode/opencode.json` under each directory with a final deny-all global and agent permission rule (V1 `permission/tools/agent` keys are ineffective). Keep concurrency low for OpenRouter. A failed cell may retry once with the *identical* prompt and route; failures remain missing after that.
3. Parse JSON events plus `opencode session export --standalone <id>`. Require exactly the expected user prompt: the OpenCode v2 export may wrap it in quotes and escape inner quotes while leaving literal newlines **and regex backslashes unescaped**. Try JSON parsing first, then the literal quoted form; require exact equality. Validate the requested provider/id/effort in session info *and* assistant message, `outcome=succeeded`, nonempty final text, no tool parts/events, and a completed non-truncated assistant response. Record actual export/session metadata and reject if any assertion is unverifiable. Protect sensitive local config; do not write full credential-bearing CLI environment into output.
4. Track reported OpenRouter cost for successful and rejected attempts, including preflight. If an exported attempted call has unknown cost, halt OpenRouter calls rather than assume zero. Before an OpenRouter dispatch, allow sufficient headroom for outstanding calls and possible spend; keep its concurrency at one and pause at USD 10. Clearly distinguish this reported value from real billing and from OAuth/`cli_proxy` zeroes.
5. Unit-test infected stdin/prompt, wrong variant, missing export, empty/truncated answer, tool use, retry/resume, duplicate ID, and OpenRouter budget pause. Validate the manifest and shuffled queue cover 300 unique cells exactly, prompt hashes fixed per case/axis across both repetitions, and source hashes unchanged.

## Task 4: launch bounded run

1. Freeze and display `manifest.json` before making API calls; run all local tests. Preflight one cell for each distinct provider family, validate session export end to end, and add those charges/attempts to the budget/accounting; do not count preflight as benchmark answer unless it is the specified cell with identical frozen prompt, route and verification rules.
2. Dispatch the 300-cell queue with a persistent log; if it runs beyond the current session, start as a background process, report its PID/log/`--status` command, and never state that pending reviews have completed. Honor USD 10 reported OpenRouter pause. If a provider rejects the fixed route, leave its cells missing and tell the user; never substitute a route after the first answer.
3. Check status, valid/invalid counts and route consistency. Do not score or publish a ranking before complete blind adjudication. If partial, publish an explicitly partial operations note instead of invented scores.

## Task 5: blind adjudication and closeout

1. Shuffle and mask answers by case before identifying the model; apply pre-frozen rubric, classify all distinct additional factual claims with evidence links; do not count plausible, unverifiable, or stylistic opinions as false. If there is no second independent adjudicator, disclose that. Save per-answer decisions in `adjudication.json` with back-references.
2. Produce `comparison.md` with per-axis target coverage, false claims, verified extra findings, inconclusives, median/distribution of per-call duration, reported cost (and limits), missing cells and routes. Compare tradeoffs, not a post-hoc combined ranking. Update root `README.md` with round-two state and result links. Preserve all first-round files.
3. Run `python3 -m unittest discover -s round-2 -p 'test_*.py'` and the runner's `--status` + integrity checks; inspect random raw records and fixture hashes. Report only verified counts and clearly identify any unfinished adjudication or cells.

## Final review focus

- Could untrusted issue/PR text or local stdin change the instruction received by a model, or could a tool-using session be counted?
- Could an interrupted, API-failed, or resumed OpenRouter call spend money without being counted or halting further calls when its cost is unknown?
- Are all three target findings provable using only the frozen fixture, applicable at the pinned commit, and distinct from hints accidentally editorialized into the prompt?
- Are provider/model/variant and both independent repetitions verifiable per saved answer? Does missing or truncated work ever count as valid?
- Can a partial run, zero-reported-cost route or post-hoc finding be misrepresented as a complete comparison or a pre-registered target?

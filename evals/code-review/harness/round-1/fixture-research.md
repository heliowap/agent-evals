This is a behavior/test standard, not a linter rule.
- **Gold — Spec (high):** The sole change sets a [class attribute `break_on_hyphens = False`](https://github.com/pallets/click/blob/20fff386596bc1a3d92e3b5c47c81e3f17083da6/src/click/_textwrap.py#L38-L50). But [`wrap_text` constructs `TextWrapper(...)`](https://github.com/pallets/click/blob/20fff386596bc1a3d92e3b5c47c81e3f17083da6/src/click/formatting.py#L62-L71), and its inherited [CPython 3.12.7 initializer, lines 112–134](https://github.com/python/cpython/blob/v3.12.7/Lib/textwrap.py#L112-L134), writes the instance attribute from a default of `True`. - **Gold — Standards (high):** [The entire commit](https://github.com/pallets/click/commit/20fff386596bc1a3d92e3b5c47c81e3f17083da6) changes only `_textwrap.py`; it adds **no regression test**, contrary to the pinned [test requirement](https://github.com/pallets/click/blob/20fff386596bc1a3d92e3b5c47c81e3f17083da6/.github/pull_request_template.md#L18-L21). A suitable assertion would compare the issue's complete expected usage output.

## 2. Explicit code-style violation and quoted-argument regression

- **Revision:** [pallets/click#3868](https://github.com/pallets/click/pull/3868), commit [`425104296015c9ffb63fbbe4d9db12d3ae0ef12a`](https://github.com/pallets/click/commit/425104296015c9ffb63fbbe4d9db12d3ae0ef12a), parent `6aabf099bfdd4c1e75fe8d0e0d4241372b988ab1`; **85 additions, 5 deletions, 2 files**. - **Documented standard:** [Click's contributing guide at this revision, lines 33–38](https://github.com/pallets/click/blob/425104296015c9ffb63fbbe4d9db12d3ae0ef12a/docs/contributing.md#L33-L38), explicitly says to avoid ternary expressions and use `if`/`else` because coverage cannot measure both branches. - **Gold — Standards (high):** The new [token-cleaning comprehension, line 693](https://github.com/pallets/click/blob/425104296015c9ffb63fbbe4d9db12d3ae0ef12a/src/click/_termui_impl.py#L690-L696), contains exactly the prohibited `x if cond else y` expression. Replace with explicit branches (or a small helper) if adhering to the documented standard.
- **Gold — Behavior against PR-stated scope (high for parsing; Windows launch not exercised here):** With `WIN=True`, the new [`shlex.split(editor, posix=False)` path and token cleanup](https://github.com/pallets/click/blob/425104296015c9ffb63fbbe4d9db12d3ae0ef12a/src/click/_termui_impl.py#L683-L705) parse `C:\tools\vim.exe --arg="a b"` as `['C:\\tools\\vim.exe', '--arg="a', 'b"']`, **not** two arguments with a single `--arg=a b`. Report this as a quoted-argument parsing regression in the PR's expanded solution, **not** as proof that issue #3840's plain `notepad` reproduction remains broken.

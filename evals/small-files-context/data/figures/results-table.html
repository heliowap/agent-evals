Result: in this setup, splitting the code into small files did not reduce context use. The estimate points the other way (+15%), but the sample is too small to say small files are worse. Every run passed in both arms, so quality didn't separate them.

Likely why (post hoc, from the transcripts)

  • With the big file, the agent never read it whole: it used grep and read slices (largest single read ≈ 3.5k tokens).
  • With small files, reading a whole file became cheap, and the agent did it 23 times in 5 of 12 runs, mostly on the cross-cutting task.

What this does not show

  • Only 3 runs per cell, one model, one codebase the model likely knows, short tasks (≤ 20 model calls).
  • Only context use was measured, not readability, code review, or merge conflicts. The pre-commit hook itself was not tested.
